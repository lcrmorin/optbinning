CP benchmark updates

The fixed reference is OptBinning 1.0.0, commit 271c906d5250f17633396f88d246d64b4c449380. Every comparison reruns both revisions together on the same runner. These are CP construction and small complete-fit controls, not predictive-performance measurements.

Construction uses 112 seeded synthetic aggregate cases. Complete fitting uses 8 controls from scikit-learn's bundled breast-cancer and diabetes datasets, using their first feature (numerical or quantile-derived categorical), with no shape constraint or native automatic shape selection. No data download is needed.

Speedup = reference time / candidate time; above 1 is faster. Each case first uses the median of 7 paired repetitions. Panel speedups and p5–p95 summarize those case medians, only for cases equivalent and eligible in all repeats. Percentiles describe case variation, not confidence intervals. Timings are median case times over all cases, including changed cases; their quotient need not equal the restricted speedup. Changed models receive no equivalent-work speedup. Fit eligibility requires OPTIMAL status and identical predictions. A changed model is not itself a failure: correctness fixes need regression tests.

Runs from different dates or protocols are not a controlled head-to-head comparison. Use the measured preceding-update comparison for incremental gains. Hosted runners are noisy; no timing threshold gates a merge.

One compact record and compressed raw measurement file per measured revision are retained here. Rerunning that revision replaces its record. This is not a collection of old notebook packages. Every code update on an enabled branch is added automatically; documentation-only changes reuse the last code record.
